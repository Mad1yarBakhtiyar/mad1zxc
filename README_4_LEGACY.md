# SKAS 4.0 — Liquid Glass 2.0

Локальное обновление интерфейса существующего SKAS 3.0. Проект не опубликован и не отправлен на GitHub. React + TypeScript, Vite, Tailwind, Recharts; исходные Supabase/PostgreSQL и Vercel Serverless Functions сохранены.

## Быстрый запуск · Windows / macOS

Установите Node.js с npm. Распакуйте ZIP, откройте папку `SKAS-4.0` в VS Code → Terminal → New Terminal.

```sh
npm ci
npm run dev
```

Откройте адрес Local, напечатанный Vite. Команды одинаковы для PowerShell, cmd и терминала macOS. `Ctrl+C` останавливает сервер.

Без переменных окружения работает исходный локальный режим: вход, дисциплины, тесты, результаты и 140 уроков. Аккаунты, PIN-коды, привязки преподавателей и ключи localStorage/sessionStorage не изменялись. Для проверки используйте свои прежние данные входа.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`dist/` — готовая клиентская сборка. `npm run preview` раздаёт её без серверных функций. `node_modules` не включён в архив, восстанавливается через `npm ci`.

## Что изменилось

- Фон с сиреневым светом слева, голубым сверху справа и розовым справа снизу; плавающая навигация и прозрачные панели, близкие к композиции референса.
- Dashboard: четыре карточки статистики, крупный график, кольцо реального прогресса, активность и нижний блок состояния.
- Обновлены Login, Subjects, Examination, Results, Learning, Messages, Teacher Panel, AI, таблицы, поля и окна. Добавлен профиль с выбором темы.
- Тёмная тема по умолчанию для новых настроек; светлая и системная доступны. Уже сохранённый выбор темы сохраняется.
- Адаптивное меню и сетки, клавиатурный фокус, сокращение анимаций по системной настройке, непрозрачный fallback при отсутствии backdrop-filter.
- Общие компоненты: `GlassCard`, `GlassButton`, `GlassInput`, `GlassSidebar`, `GlassModal`, `ThemeToggle`; дизайн-токены в `liquid-glass.css`.
- Исправлен перехват `/api.ts` Vite proxy: теперь проксируются только URL `/api/…`.
- Добавлен `api/chat.js`: существующий обработчик AI теперь доступен по URL `/api/chat`.

Содержимое, показатели и подписи адаптированы к обучению. Финансовые цифры из референса не подставляются; без результатов график показывает честное пустое состояние. Это визуальная реконструкция, а не гарантия попиксельного совпадения.

## Существующий сервер и Supabase

Полный разбор исходной архитектуры и ограничения — в `VERIFICATION.md`. Важно: **в присланном SKAS 3.0 тесты и результаты уже хранились в браузере**, даже при включённом Supabase. Этот редизайн не переносит их в PostgreSQL и не меняет схемы данных.

Сервер обслуживает `/api/school` (вход, дисциплины переписки, сообщения, прогресс) и `/api/chat` (AI). Для подключённого режима нужны:

| Переменная | Где используется |
|---|---|
| `VITE_SKAS_BACKEND=1` | Клиентский переключатель существующего backend-режима |
| `SUPABASE_URL` | Только сервер |
| `SUPABASE_SERVICE_ROLE_KEY` | Только сервер; никогда не добавляйте `VITE_` |
| `SKAS_SESSION_SECRET` | Только сервер, минимум 32 символа |
| `OPENAI_API_KEY` | Только сервер, для AI |
| `OPENAI_MODEL` | Необязательно, существующая настройка модели AI |

Секреты отсутствуют в архиве. `.env.example` содержит только пустые поля. Не помещайте реальные `.env` в клиентскую сборку или ZIP.

Обычный Vite не запускает Vercel Functions. Для полноценной локальной серверной проверки используйте существующую Vercel-конфигурацию через Vercel CLI (`vercel dev`) с переменными окружения. **Не выполняйте `vercel` / `vercel --prod` для публикации до отдельного согласования.** В обычном Vite запросы `/api/…` проксируются на `127.0.0.1:8000`, как было в исходном проекте; там должен работать совместимый сервер, если вы используете этот способ.

Для существующей базы **не запускайте заново `SUPABASE_SETUP.sql`** ради редизайна. SQL сохранён без изменений как справочный исходный файл. Старые README описывают версии 2/3 и их первоначальную настройку; этот README описывает версию 4.

Проверяйте реальные сообщения, серверный вход и прогресс на отдельной тестовой базе. С рабочей базой допустимы только согласованные проверки без изменения данных. Доступа к ней при подготовке этого архива не было.

## Сохранение существующих данных при обновлении

Данные в Supabase не затрагивались. Для сохранения браузерных тестов, результатов и прогресса после будущей публикации используйте тот же origin (протокол + домен + порт), тот же браузер и не очищайте его хранилище. Новый локальный адрес не наследует localStorage рабочего сайта. Ключи `skas-v2-demo-data`, `skas-learning-progress-*`, `skas-theme`, `skas_token` и `skas-user` сохранены.

## Проверки и файлы

`VERIFICATION.md` — фактически выполненные проверки и то, что проверить не удалось.

`CHANGED_FILES.md` — список добавленных/изменённых файлов. `npm test` запускает 18 групп изолированных проверок с хранилищем в памяти и подставным HTTP; не обращается к реальной базе.
